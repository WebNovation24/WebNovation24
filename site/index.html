Engineering focus

The recurring problems I want to work on are the ones where product behavior depends on explicit technical boundaries, not just UI state.

Tenant scope

Keep identity, membership, capabilities and data access explicit so UI visibility never becomes the security boundary.

Workflow correctness

Model critical operations as state transitions with clear authority instead of optimistic completion.

Data integrity

Reinforce application contracts with durable data boundaries where multi-tenant state matters.

Async work

Move long-running or external work out of request paths while preserving observable operation state.

Verification

Treat tests and release gates as scoped evidence, not proof of infallibility.

Evidence before assumptions

I prefer to make authority, constraints and failure states explicit before optimizing the happy path. That means separating product intent from runtime truth, defining what a test actually proves, and keeping release evidence tied to the exact candidate being evaluated.
